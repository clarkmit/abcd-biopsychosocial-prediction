    API reference¶

    The public API is small: build a PipelineConfig, run a Pipeline, inspect ctx.

    Pipeline¶

    Orchestrates one analysis session.

    Parameters:

    Name Type Description Default
    config PipelineConfig | None

    Full run configuration. config.setup.DATA_PATH must point at the merged multi-wave panel (or at the simulated panel shipped in data/simulated). Relative paths (data and output directory) are resolved against the working directory at the time the pipeline is created.

    		 None
    Notes

    The pipeline keeps a reference to config: settings changed between stages apply to the next stage, as editing a form field before running a notebook cell did. All tables and figures are written to config.output_dir.

    output_dir property ¶

    Absolute output directory of this session.

    data_path property ¶

    Absolute path of the analysis panel (config.setup.DATA_PATH).

    setup() ¶

    Start a fresh session: load data and build feature registries (cells 0-5).

    run_stage(stage) ¶

    Run one analysis stage (equivalent to running its notebook cell).

    run(stages=None) ¶

    Run setup and then stages (default: config.stages).

    Temporarily run inside path; stages write their tables and figures there.

    Configuration¶

    Complete run configuration (one YAML file).

    stages = field(default_factory=lambda: ['main']) class-attribute instance-attribute ¶

    Stages to run after setup, in order (see ALL_STAGES).

    output_dir = 'outputs' class-attribute instance-attribute ¶

    Directory that receives all tables, figures and logs of the run.

    model_overrides = field(default_factory=dict) class-attribute instance-attribute ¶

    Per-model hyperparameter overrides, e.g. {"catboost": {"iterations": 300}}.

    stage_settings(stage) ¶

    Settings applied to the run context before stage runs.

    validate() ¶

    Check stages, setting types and drop-down values; raise ValueError on the first problem.

    from_dict(data) classmethod ¶

    Build a config from a (possibly partial) nested dict; missing keys keep defaults.

    YAML numbers given for text settings (tp_option: 2) and null for settings whose allowed values include "None" are converted to the expected strings.

    Run context¶

    bpsp.ctx is the single RunContext instance shared by all stages.

    Bases: dict

    A dict with attribute access, holding the state shared between stages.

    register(module) ¶

    Expose a stage module's definitions, as executing the notebook cell did.

    Later stages look some helpers up by name at run time; registering a stage before it runs reproduces the notebook's "defined once the cell has run" behavior.

    reset() ¶

    Clear all state (start of a new session).

    variables() ¶

    Data entries only (settings and results), without registered functions, classes or modules.

    Convenient for inspection, e.g. sorted(ctx.variables()).

    Bases: AttributeError

    Raised when a stage reads a context entry that no earlier stage produced.

    The notebook raised NameError for an undefined global; an AttributeError subclass keeps getattr/hasattr/copy working on the context object.

    Simulated example data¶

    Simulated panels with a known answer, for demonstrations and tests.

    The panel shipped in data/simulated/ draws every column independently, so no outcome can be predicted from it. :func:make_example_panel resamples it to a chosen number of subjects and plants a known structure at wave T2 (time == 2), so that a run has a correct answer to recover:

    • a latent score drives three parent-report CBCL items (stubborn_p, disagreeable_p, blames_others_p, recorded as 0/1/2);
    • the CBCL internalizing and depression T-scores (internal_D_p, depress_D_p) are 55 + 6 * (0.8 * latent + 0.6 * delta_not_liked_p + noise), and the externalizing score (external_D_p) uses 0.7 times the same signal;
    • the binary depression targets of the "Child Depression Worsening" batch (top_10_depression, top_5_depression, dep_increase_1.5sd, dep_increase_2sd) are thresholds of that signal;
    • the noise standard deviation is 1.3 instead of 0.8 for participants with desc_latin_B == 1, so the subgroup analyses have a real difference to detect.

    Everything else carries no information, and baseline demographics are held constant within subject. The data remain fully synthetic.

    PLANTED_FEATURES = ('stubborn_p', 'disagreeable_p', 'blames_others_p', 'delta_not_liked_p') module-attribute ¶

    Predictors that carry the planted signal at T2.

    make_example_panel(source, n_subjects=1200, seed=0) ¶

    Return a simulated panel of n_subjects x 5 waves with the planted signal described above.

    Parameters:

    Name Type Description Default
    source str | Path

    The simulated panel shipped with the repository, data/simulated/CLEAN_ABCD_5_1_panel_simulated.csv.

    		 required
    n_subjects int

    Number of simulated participants (rows per wave).

    		 1200
    seed int

    Seed for resampling and for the planted signal; the same arguments give the same panel.

    		 0

    Logging¶

    bpsp.configure_logging:

    bpsp._logging.configure_logging(level='INFO', fmt='%(message)s', logfile=None) ¶

    Send bpsp log records to stdout (and optionally a file).

    Calling it again changes the level and format; a log file is attached only once.

    Parameters:

    Name Type Description Default
    level int | str

    Logging level, e.g. "INFO" (default) or "WARNING" for quiet runs.

    		 'INFO'
    fmt str

    Record format. The default reproduces the notebook's plain printed output.

    		 '%(message)s'
    logfile str | None

    Optional path; records are also appended there with timestamps.

    		 None
    Notes

    Records do not propagate to the root logger, so stage output is not printed twice in environments that configure root logging. To route bpsp output into your own logging setup instead, attach handlers to logging.getLogger("bpsp") before the first run; the default console handler is then not added.
